# 看板信号与时间窗口

2026-11-13 用户补充：在原有三个 1H 门槛之后，排除 1H 手续费环比与价格涨跌同时为空（null）的池；任一指标有值（包括 0）则保留。此规则用于数据筛选，不代表诈骗鉴定；刚建池或比较数据缺失的正常池也可能被排除。六窗口共用筛选后的集合，长窗口缺档不额外删行；保留池目录与小时档，不改变采集及旧版 v1 接口口径。

2026-11-12 本轮更新以 [统一方案](05-data-repair-and-1h-filter.md) 为准：默认 TVL ≥ $1,000、1H 成交量 ≥ $100、1H 普通 LP 手续费 ≥ $10 统一准入；各窗口同池集合，新增 4H，3D 取代 7 天。费用质量标签已按用户要求撤销，缺失显示「—」。3D 代码已切换至本机运行；最新实际覆盖及采集核对见方案 05 第 5 节。

不要把这些数字当成同一个信号。成交量和 APR 是发现层的主要参数；Fee 能否覆盖 IL 才是判断这笔 LP 值不值得做的不等式。Fee 对 IL 这一列第一期先不定。

| 项 | 规则 |
| --- | --- |
| 筛选 | 按链、协议、费率档筛选；按代币或交易对搜索 |
| 默认过滤 | TVL ≥ $1,000、1H 成交量 ≥ $100、1H 普通 LP 手续费 ≥ $10；各窗口同池集合，不设 APR 门槛；TVL 与成交量门槛可改 |
| 默认排序 | 按 1 小时 fees APR 从高到低 |
| 可排序字段 | TVL、成交量、手续费、fees APR（可设门槛）。Fee 对 IL 列暂缓 |
| 刷新 | 手动刷新与后台每 5 分钟续接扫描共用管线；服务启动先扫一次，忙则跳过；浏览器不主动拉源，仍按数据版本载入已发布结果 |
| 展示 | 同一交易对分行展示，不合成一行；看板上要标 hook 类型 |

| 信号 | 作用 | 边界 |
| --- | --- | --- |
| 链、协议、费率档、代币对 | 切片和搜索，不评优劣 | 必须有，但不能回答这个池能不能做 |
| 成交量 | 用来判断有没有真实流量 | 不得用成交量乘费率档去推手续费。仍要对多时间窗口，防止刷量、短时狂拉或 JIT 把单日数字拉高 |
| TVL | APR 的分母，也大致代表能放多大资金、滑点有多大 | TVL 极低时 APR 会虚高，且放不进规模；必须和成交量、APR 并排 |
| 手续费额（绝对值） | 这段时间池子真正赚到了多少钱，比年化 APR 更不易被短窗口放大 | 仍需要看窗口；不包含自己区间的占比和 IL |
| fees APR | 发现层的主要排序信号，用来把相对 TVL 足够热的池筛出来 | 只用窗口内实际归 LP 的手续费年化，不能用费率档乘成交量。协议费和 hook 费不算进 LP 收益。池的 APR 不等于某个区间的 APR；短窗口年化会过度放大；不含 IL，不能当入准结论 |
| Fee 对 IL | 判断层不等式：预期手续费能否覆盖价格变动带来的无常损失 | 列定义暂缓。以后若做，必须写明估计用的区间宽度、持有时长和价格冲击假设 |

## 窗口与过滤

能用官方档的都用官方档，默认看 1 小时。表里「官方」是协议预汇总档，「加总」是把更短的官方档加起来，「自建」是从成交日志自己汇总。

Elysium 作为第一期第一条，没有官方档，已定窗口必须自建并如实展示，不得空着，也不得用其他窗口冒充。Raydium 以及暂无索引的 BSC Uniswap V4 与 Pancake Infinity，轮到该协议时能自建则自建，否则空着或标明后回退，不得拿别的窗口冒充。

已定窗口为 1 小时、2 小时、4 小时、6 小时、24 小时、3 天。30 分钟和 30 天以后再作看板档。默认按 1 小时 fees APR 从高到低排序。过滤条件全链全协议统一，门槛可改。1H 至 24H 在数据完整时可比较上一等长窗口；3D 用于参考 24H，3D 自身环比不作为必需指标。第一期保留手动刷新，并启用服务端每 5 分钟续接扫描；扫描周期与指标窗口不是同一件事。5 分钟只更新正在进行的那条 1 小时记录，不把 5 分钟升为已定看板档。钱包和只读仓位先完成设计，实现等扫描验收通过后再做。

## 手续费可信度修复（2026-11-12）

用户要求逐项查清有 TVL、有成交、手续费为 0 的记录。保持「仅统计实际归 LP 的手续费，协议及 Hook 自收费不得混入」的既定口径；未知不得显示成已确认的零。

- `verified_zero`：无 Hook、固定 LP 费率为 0 的 V4 池，且该档原始 LP 费用为 0，可确认核心交易 LP 费为 0。它不包含主动捐赠或外部奖励。
- `hook_unresolved`：此前按 Hook 一律留空的历史档，保留原值并安排重扫。新重扫的核心交易 LP 费用按逐笔事件扣除协议费计算，不因存在 Hook 置空；核心费零也保留零。独立 Hook 收费及外部收益未经核实不计入，不据核心零费断言全部收入为零。
- `legacy_unverified`：修复前 V4 使用了错误输入币方向的历史档。重扫前手续费与派生指标留空；不改写历史原始值来伪造修复。
- `protocol_state_missing`：V3 或 V4 无法确定协议费状态，手续费与派生指标留空，不能默认协议费为 0。
- `estimated`：按逐笔成交事件及已读取的协议费参数重建，含有 Hook 池可证明的核心 LP 费用。状态与原因保留在数据中，页面不增加费用质量标签；跨 tick 的逐步取整和历史协议费参数尚未逐笔重放，不得宣称精确对账通过。V3 现有重建算法同样保留此限制。

V3 Swap 为正数的一侧是输入；V4 BalanceDelta 为负数的一侧是输入，费用归入该输入币。方向修复必须同时覆盖解码、协议费拆分、小时汇总，真实日志夹具须断言输入币和金额。

手续费状态随小时档保存，多小时合并只要有不可用费用档，手续费及派生指标不得用剩余部分冒充完整值。API 追加状态和原因，不改原有 value 可为 null 的合同。已结束但未补齐的小时必须显示覆盖缺口，不得当作已完整扫描。

具体链上证据及未解决项见 `docs/03-data/04-fee-investigation.md`。本修复不代表扫描验收通过。
