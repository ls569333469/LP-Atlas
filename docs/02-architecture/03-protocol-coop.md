# 多协议如何配合

这些协议不是一套互相调用的系统，而是各自独立的流动性场所。产品用同一套看板把它们放在一起看、用同一套模板去铺；执行时仍然各走各的链、各签各的合约。跨链不能原子成交。同一交易对在不同协议里是不同的池，看板上分行展示，方便比较哪里更热、费率怎么收，不要合成一行。后期再把 Base 上的 Pancake 与 Meteora DAMM V2 按同样方式分行接入。

| 关系 | 怎么配合 | 注意 |
| --- | --- | --- |
| 同一条链上的多个协议 | 例如 BSC 上同时有 Pancake V3、Infinity、Uniswap V3 和 Uniswap V4。扫描规则相同，结果放在同一张表里比 | Infinity 是 Vault 加 CL 或 Bin 的 PoolManager，Uniswap V4 是单一 PoolManager，适配器必须分开写 |
| V3 和 V4 / Infinity | 过滤、排序和区间模板可以共用；V4 与 Infinity 多了 hook 和动态费，看板上要标 hook 类型 | Aggregator Hook 这类池不是普通集中流动性仓位，不能按同一套开仓逻辑推荐 |
| EVM 和 Solana | 归一后都是同一套区间、TVL、成交量、实际手续费和 fees APR；Spot / Curve / Bid Ask 模板也可以映射过去 | 接入方式不同，新鲜度按各自出块时间算；Raydium 同一交易对同一费率现在可以有多个池 |
| Elysium 和其他 EVM | 合约和 SDK 已是 Uniswap 官方部署，适配器对齐官方地址；窗口仍须自建 | 生产用带归档的节点；读当前状态优先用官方 StateView，不要只扫日志 |
| 资金怎么分配 | 全站扫描、统一门槛过滤后，由用户选池；后期每个仓在自己的链上独立开、独立撤 | 不要设计跨协议或跨链的原子加池，链上做不到 |
