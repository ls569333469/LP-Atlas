# 20 · 代币分组、FDV 与价格档位间距

2026-11-23（北京时间）。范围为 Elysium 与 Robinhood 的 Uniswap V3/V4、Solana 的 Meteora DLMM。用户确认增加代币分组、FDV 和价格档位间距，并要求接通前后端字段、筛选和页面布局。本文记录方案，实施进度见 [05 唯一执行清单](../04-standards/05-roadmap.md)。

## 1. 展示对象与分组

- 保留现有「按池」视图，默认沿用现有视图与排序。新增「按代币」视图，按 `chain + tokenAddress` 标识组，保留 EVM 地址归一和 Solana Base58 大小写规则。每个池在一次分组结果中出现一次。
- 建议使用各链已核实的常见报价资产地址。只有一侧为报价资产时归入另一侧。两侧均是报价资产或均是普通资产时，以稳定的地址顺序选组，池详情仍显示原交易对。具体报价资产表和双普通币归组规则在实施前复核。
- 两视图复用同一份发布快照。先执行原准入和用户筛选，再按当前排序排列匹配池，之后分组、分页。组头代表池是该组当前排序下的首池，注明交易对和所用排序指标。组内沿用同一排序与稳定次序。按池页显示池数，按代币页显示组数和匹配池数，展开随当前快照读取全部匹配子池。

## 2. 字段从采集到前端

| 字段 | Elysium / Robinhood | Solana | 看板接口与展示 |
| --- | --- | --- | --- |
| 代币 FDV（美元） | 按代币身份对已准入候选去重，后台批量读取 ERC-20 `totalSupply()`，用 decimals 换成人类单位，与已核有效的同链代币美元价计算 | 复用已采集的 `token_x/y.total_supply` 和 `price`。先核供应量单位和价格含义，按同一公式计算 | 每侧代币附可空 FDV、来源和估值时点；分组行以分组代币显示，按池详情标明代币身份 |
| 价格档位间距 | 复用池目录 `tickSpacing` | 复用官方池资料 `binStep` | 共享类型区分 `tickSpacing`（tick）和 `binStep`（bps），接通池行、详情、筛选和快照分页 |

- FDV = 总供应量 × 每枚代币的美元价。用十进制计算，展示层统一格式化美元。价格必须能对应到合约地址、币种和有效时点。EVM 先核现有估值链路能暴露哪些有效代币价格，再确定复用入口。无有效价格、供应量读取失败或数据过期时显示缺值；保留已知输入和来源供诊断。
- EVM 供应量按链和地址缓存，由低频任务更新，成功样本记读取时间。五分钟采集与看板请求均不等待代币 RPC；看板只读本地结果。Solana 复用现有发布字段。间距字段直接读取既有数据，三链均不增加采集请求。
- 供应量、价格与 FDV 按发布或查询快照冻结。相同快照的列表、分页、详情和两种视图引用同一值，避免刷新时看见口径不一致。暂不接入持有人数、流通市值或代币上线时间。

## 3. 筛选与前后端约定

- 现有漏斗「通用筛选」增加 FDV 最低／最高，美元单位，可只填一端，端点包含。按池可选任一侧、X／Y（EVM 为 Token 0／1）或两侧，默认任一侧，同一代币满足上下限。按代币以组头代币的 FDV 匹配。建议将侧选择仅用于按池视图，切换视图保留此前设置。
- 间距采用协议专属条件。Uniswap V3/V4 增加「刻度间距」最低／最高，Meteora 直接复用现有 DLMM「分箱步长」，沿用 bps 单位。全部网络里的专属条件只筛对应协议的池。两类间距各自校验和应用。
- 默认都留空；填写时与原条件按 AND 组合，字段缺值时只影响该项已启用的筛选。视图、输入与筛选状态可通过 URL 恢复，统一支持应用、清空和有效条件数。API 校验范围与单位，应用全量筛选后再分页，主表、详情与切链复用相同字段。原外露排序继续可用，新增字段排序列为待确认项。

## 4. 前端排版

- 现有工具栏放「按池 / 按代币」切换，搜索、排序和漏斗保留在原查询区。筛选仍用中央弹窗，右侧继续服务池详情和交易面板。参照 [07 前端标准](../04-standards/07-frontend.md) 的列宽、边距、数字对齐和窄屏横滚。
- 按代币视图用单行组头显示展开按钮、代币名、网络、匹配池数、FDV、代表池及当前排序值。默认折叠，金额右对齐；池行缩进显示交易对、协议、费率和价格档位间距，保留六窗和详情入口。Solana 显示「Bin Step 50 bps」，EVM 显示「刻度间距 50 ticks」。字段说明可悬停、键盘聚焦；缺值用 `—`。
- 按池视图沿用现有六窗排版。费率和档位间距在池身份区就近显示，FDV 可在池详情按两侧代币查看和在漏斗筛选。检查窄屏、长币名、右侧详情展开、多个组展开和翻页，避免挡住费率、间距或操作按钮。
- [LP Agent Discover](https://app.lpagent.io/discover?sortBy=vol_change_24h) 用于参考组头与展开层级。

## 5. 验收

1. 同币跨报价资产、同币不同协议／费率、同名不同地址、跨链同名和双普通币均可复核。分组前后匹配池集合符合对应筛选，所有页无重复池或拆组。全部网络内同链结果与该链视图一致。
2. 三链各选代表池核对单位、价格与供应量来源、FDV 算式、间距原值，以及字段从存储、接口、筛选到列表和详情的一致性。断源、缺值、过期、单端范围、边界等值、切链与恢复默认均纳入验收。
3. 核三链实时页面和查询耗时，另外对照五分钟采集的请求数与实际扫描耗时。FDV 补充任务的失败不影响原信号发布。P19 仍按自己的 05 清单验收。

## 6. 右侧池详情与外部入口

2026-11-23 调研与设计，代码待执行。

### 6.1 现状与排版

- `EntryPlaceholder.tsx` 在「新建仓位」面板内渲染 `PoolMetrics`。目前池 ID、复制按钮、TVL／池龄／费率、Hook 回调和两个代币地址混在连续文本里。主表已显示同一份看板快照的六窗口指标，右栏再次画矩阵会引入横滚。候选池对照也复用 `PoolMetrics`，实施时需要把右侧详情与对照展示区分开。
- 右栏以交易对为标题，下一行放网络和协议。风险标签及收益归属紧邻标题。TVL、池龄、费率分格排列，窄栏允许换行。池 ID 单独成组，地址按可用宽度折行，复制和「官方池页面 ↗」放同一操作区。两个代币各占一行，显示币名、CA、复制和可用的「看 K 线 ↗」。长地址折行区域可以完整选取，操作按钮不挤进地址文本。
- Hook 地址与回调放入独立、可展开的「Hook 权限」区。主表已显示的六窗口矩阵，以及「价格与流动性 · 待开发」占位从右侧详情移除。保留来源与截止时间、池级风险提示和 DLMM 专属资料。候选池对照继续提供跨池六窗对比。主表的六窗口指标和 P20 已规划的主表展示按原设计推进。
- ETH/UNIWALL 示例中，ETH 为原生资产，无 CA 时标为「原生资产」。UNIWALL 一行显示 `0x255979302fd6a5e2ff6dce0d8b018f51e06e243a`，池 ID 单独显示。开仓占位和池详情保留现有右栏入口及关闭、返回行为。

### 6.2 官方池与 K 线导航

| 用途 | 定位键 | 已核依据与实施条件 |
| --- | --- | --- |
| Uniswap V3/V4 官方池 | 链 + 池标识 | 官方界面源码的路径是 `/explore/pools/:chainName/:poolAddress`，链参数已核为 `robinhood`、`elysium`。V3 传链上池合约地址，V4 传 32 字节原始池 ID。样例请求返回 HTTP 200，仍需在页面确认目标池资料读出。 |
| Meteora DLMM 官方池 | Solana 原始池地址 | 使用 `https://app.meteora.ag/dlmm/<poolAddress>`，保留 Base58 大小写；库内 SOL/USDC 样例页面请求返回 HTTP 200，实施时核页面内的交易对与地址。 |
| 代币 K 线 | 链 + 代币 CA 或 Solana Mint | 每个代币独立提供入口，点哪一侧就用那一侧地址，保持 Solana Mint 大小写。GMGN 的测试请求返回 403，AVE 的 Robinhood 路径按不同链参数返回 404 或通用页面，尚未证实能按 CA 打开正确代币。逐链核实实际渲染后才启用对应入口。 |
| 可选的当前池 K 线 | 链 + 原始池标识 | DexScreener 的公开接口能按合约查到 UNIWALL 的多个池，并返回本池的精确图表地址。Elysium 和 Solana 样例也返回匹配池。若代币页供应商还未核实，可采用明确标为「池 K 线 ↗」的入口，保持当前费率档与池 ID。Solana 样例的供应商 URL 使用小写路径，内部池身份和官方链接仍保留原始 Base58。 |

- 所有外链使用已核链／协议／服务商路由，在新标签页打开。缺乏可确认的目标时只提供复制，避免用同名代币、其他网络或另一费率档替代。外链是用户主动导航，详情渲染、看板请求和后台采集新增外部请求均为零。保持现有快照与 API 计算口径。
- 复核入口：[Uniswap 官方路由](https://github.com/Uniswap/interface/blob/c4fb7d8f6bf4eac1a0b633a0c6b9e22387a4a3cc/apps/web/src/pages/routes/RouteDefinitions.tsx)、[官方链 URL 参数](https://github.com/Uniswap/interface/blob/c4fb7d8f6bf4eac1a0b633a0c6b9e22387a4a3cc/packages/chains/src/chainMetadata/chainMetadata.ts)、[UNIWALL 官方池](https://app.uniswap.org/explore/pools/robinhood/0xa8f330994e5832b499e1c82921846f423a20ba7601fe9b42340715d2f81c8bd0)、[Meteora SOL/USDC 样例](https://app.meteora.ag/dlmm/5rCf1DM8LjKTw4YqhnoLcngyZYeNnQqztScTogYHAS6)、[DexScreener UNIWALL 池查询](https://api.dexscreener.com/token-pairs/v1/robinhood/0x255979302fd6a5e2ff6dce0d8b018f51e06e243a)。

### 6.3 页面验收

1. 用 ETH/UNIWALL 核对窄栏中的长池 ID、CA、复制操作和风险提示。右栏无六窗矩阵及价格流动性占位，主表和候选池对照的六窗仍可用。
2. 各选 Uniswap V3、V4 和 Meteora DLMM 代表池点击官方入口，校对实际页面的网络、协议、池标识及交易对。代币 K 线按各自 CA 或 Mint 核对，池图表另核精确池；覆盖原生资产、无已核服务商、跨链同名和同币多池。
3. 关闭详情或返回目录后，原筛选、排序、页码和滚动位置保持。核对详情加载与开仓占位仍可用，外链只有主动点击才访问。

## 7. 实施前复核（2026-11-23）

- **分组与分页**：同一发布快照、同一网络与协议筛选应复用同一池数据。按代币分组先为每个池确定组键，再按该组代币 FDV 过滤；排序后选代表池，最后按组分页。按池视图使用代币侧选择，因此切换视图时漏斗须标明 FDV 匹配对象。报价资产地址表与双普通币的归组仍待复核。
- **FDV 与间距**：代币 USD 单价、池内兑换比例、流通市值分开。核实供应量单位、原生资产及包装资产身份和缺值行为后再接入。EVM 刻度间距与 DLMM 分箱步长沿用各自单位及过滤入口，复用已有 DLMM 条件。字段需贯通共享类型、API、快照、漏斗、主表和详情。FDV 补充任务的延迟或失败不能阻塞五分钟发布。
- **主表和详情**：主表继续提供既有价格涨跌和六窗指标。价格曲线、流动性分布及区间叠加作为主页面方向，目前仍待明确展示合同与数据来源。右侧删除相应的待开发占位及重复六窗口表，保留风险、来源和官方池入口。代币 K 线与精确池 K 线按第 6 节分别验证。
- **执行边界**：P20 进度见 05。Meteora 五分钟采集性能单独按 [P21](21-Meteora-DLMM五分钟采集性能-2026-11-23.md) 测速与验收，先取得可比基线，再评估 P20 新字段的额外开销。
