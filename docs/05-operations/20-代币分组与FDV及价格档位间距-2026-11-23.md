## 1. 展示对象与分组（暂缓，保留设计记录）

- 默认进入「按代币」，仍可切换「按池」查看六窗。组键为链 + 代币 CA 或 Mint，EVM 地址统一小写，Solana Mint 保持原大小写。
- 匹配池按两侧资产地址分别加入对应组。不同报价币、协议或费率下的同地址池均进入同一组。同一池可出现在两个不同代币组，每组内按链、协议、池 ID 去重，全站池数按池身份去重。
- 两视图复用同一份发布快照。先执行原准入和用户筛选，再按当前排序排列匹配池，之后分组、分页。组头代表池是该组当前排序下的首池，一级沿用该首池的 TVL、池龄和全部六窗口指标，一级仅用简短的「数据取自」标明池名，展开子表展示完整交易对信息。组内沿用同一排序与稳定次序。按池页显示池数，按代币页显示组数和匹配池数，展开随当前快照读取全部匹配子池。

## 2. 字段从采集到前端

| 字段 | Elysium / Robinhood | Solana | 看板接口与展示 |
| --- | --- | --- | --- |
| 代币 FDV（美元） | 按代币身份对已准入候选去重，后台批量读取 ERC-20 `totalSupply()`，用 decimals 换成人类单位，与已核有效的同链代币美元价计算 | 复用已采集的 `token_x/y.total_supply` 和 `price`。先核供应量单位和价格含义，按同一公式计算 | 每侧代币附可空 FDV、来源和估值时点；分组行以分组代币显示，按池详情标明代币身份 |
| 价格档位间距 | 复用池目录 `tickSpacing` 并换算为基点 | 复用官方池资料 `binStep` | 池行、详情、筛选和快照分页共用基点口径，保留原字段 |

- FDV = 总供应量 × 每枚代币的美元价。用十进制计算，展示层统一格式化美元。价格必须能对应到合约地址、币种和有效时点。EVM 先核现有估值链路能暴露哪些有效代币价格，再确定复用入口。无有效价格、供应量读取失败或数据过期时显示缺值；保留已知输入和来源供诊断。
- EVM 供应量按链和地址缓存，由低频任务更新，成功样本记读取时间。五分钟采集与看板请求均不等待代币 RPC；看板只读本地结果。Solana 复用现有发布字段。间距字段直接读取既有数据，三链均不增加采集请求。
- 供应量、价格与 FDV 按发布或查询快照冻结。当前逐池看板的列表快照、分页、筛选和详情引用同一份 FDV 值。FDV 标签显示在右侧指标区和漏斗。Solana 官方 `market_cap` 保留在原资料字段。本期暂不新增流通市值、持有人数或代币上线时间。

## 3. 筛选与前后端约定

- 现有漏斗「通用筛选」增加 FDV 最低／最高，美元单位，可只填一端，端点包含。按池可选任一侧、X／Y（EVM 为 Token 0／1）或两侧，默认任一侧，同一代币满足上下限。按代币以组头代币的 FDV 匹配。建议将侧选择仅用于按池视图，切换视图保留此前设置。
- 间距采用一套通用最低／最高条件，适用全部网络，单位为基点。DLMM 直接用 `binStep`。Uniswap V3/V4 使用 `(1.0001^tickSpacing − 1) × 10,000`，显示和筛选同取最多四位小数。保留原始数据。旧 URL 和 API 中的刻度、分箱条件保持原适用范围，可在漏斗清除或由通用档位条件替换。
- 默认都留空；填写时与原条件按 AND 组合，字段缺值时只影响该项已启用的筛选。视图、输入与筛选状态可通过 URL 恢复，统一支持应用、清空和有效条件数。API 校验范围与单位，应用全量筛选后再分页，主表、详情与切链复用相同字段。原外露排序继续可用，新增字段排序列为待确认项。

## 5. 验收

第 1 项的分组检查留待分组阶段。同链视图与全部网络同发布一致性、字段和性能检查属于本期。

1. 同币跨报价资产、同币不同协议／费率、同名不同地址、跨链同名和双普通币均可复核。分组前后匹配池集合符合对应筛选，各组内无重复池、分页不拆组，两个代币组可引用同一池。全部网络内同链结果与该链视图一致。
2. 三链各选代表池核对单位、价格与供应量来源、FDV 算式、间距原值，以及字段从存储、接口、筛选到列表和详情的一致性。断源、缺值、过期、单端范围、边界等值、切链与恢复默认均纳入验收。
3. 核三链实时页面和查询耗时，另外对照五分钟采集的请求数与实际扫描耗时。FDV 补充任务的失败不影响原信号发布。P19 仍按自己的 05 清单验收。

## 7. 实施前复核（2026-11-23）

- **分组与分页**：同一发布快照、同一网络与协议筛选应复用同一池数据。按代币分组先按每个池两侧地址确定组键，再按该组代币 FDV 过滤；排序后选代表池，最后按组分页。按池视图使用代币侧选择，因此切换视图时漏斗须标明 FDV 匹配对象。同池可被不同组引用，组内和全站池数按池身份去重。
- **FDV 与间距**：代币 USD 单价、池内兑换比例、流通市值分开。核实供应量单位、原生资产及包装资产身份和缺值行为后再接入。EVM 刻度间距与 DLMM 分箱步长沿用各自单位及过滤入口，复用已有 DLMM 条件。字段需贯通共享类型、API、快照、漏斗、主表和详情。FDV 补充任务的延迟或失败不能阻塞五分钟发布。
- **主表和详情**：主表继续提供既有价格涨跌和六窗指标。价格曲线、流动性分布及区间叠加作为主页面方向，目前仍待明确展示合同与数据来源。右侧删除相应的待开发占位及重复六窗口表，保留风险、来源和官方池入口。代币 K 线与精确池 K 线按第 6 节分别验证。
- **执行边界**：P20 进度见 05。Meteora 五分钟采集性能单独按 [P21](21-Meteora-DLMM五分钟采集性能-2026-11-23.md) 测速与验收，先取得可比基线，再评估 P20 新字段的额外开销。

### 8.2 分组、排序与分页

复用池身份 `chain + protocol + poolId`。服务器从同一发布的两侧资产建立 `chain + tokenAddress/mint` 到池的成员关系。组名来自该地址对应的元数据，保留网络与完整地址复制。以完整地址或精确代币简称搜索时只显示匹配的代币组，按交易对或池 ID 搜索时可展示匹配池及其组。

服务端按原 1H 准入、网络、协议和搜索取候选，再应用现有组合条件与 P20 字段。按池 FDV 默认任一侧，同一侧须满足上下限；按代币使用组键对应代币。两种视图共享池和字段值，启用 FDV 后结果集合可能因匹配对象不同而变化。全量排序后，按代币视图以组内首池作为代表，组头显示该代表池的全部主站窗口指标，窗口排序仍使用当前所选字段。服务端先分组再按组分页，折叠时只传组摘要；展开从同一 `snapshotId` 按组加载子池，超大组内分页。新快照保留仍存在的组身份及详情选择，复用原发布失效与恢复逻辑。

### 8.3 排版与实施验证

- 搜索、协议、池子费率、排序和漏斗沿用主站查询工具栏，网络继续放在市场标题行。按池／按代币切换置于列表的分页控制旁，避免挤压原有查询控件。漏斗沿用中央弹窗，通用页新增 FDV，Uniswap 页放 tick，DLMM 页复用现有条件。预览仅展示此次新增与直接相关的筛选，实施仍保留现有指标与协议选项。
- 两视图共用主站六窗列结构。按代币时，一级的 TVL、池龄和全窗口指标均取组内当前排序首池；代币 FDV 按分组地址读取。二级池行展示交易对、协议、池子费率和「价格档位间距」，并可复制池 ID。已确认的收益归属提示随对应池数据展示。右栏保留完整池 ID、代币地址、Hook 与来源。
