## 怎么启动和恢复

1. 先看 `http://127.0.0.1:3001/api/v1/health`。确认当时没有正在跑的刷新，再动手。不要无故停掉页面服务。
2. 确认本机 `.env` 已有 `ROBINHOOD_RPC_URL`，并把 `AUTO_SCAN_ENABLED` 改为 `true`。只改这一项开关，不要打印或改写密钥本身。没有备用地址就保持 `ROBINHOOD_RPC_URL_BACKUP` 为空。
3. 按运行说明重启**已在跑的那一个**编译版 API，使新环境变量生效：先 `pnpm build`，再停掉旧的 API 进程，然后 `pnpm start`（即 `node dist/server/index.js`）。后端构建必须把 `src/store/migrations` 复制到 `dist/store/migrations`。电脑开发看板若 5173 已在跑，不必再新开一套开发服务；不要留下多余的开发进程。
4. 重启后立刻再看健康接口：Robinhood 的 `rpcSource.kind` 必须是 `configured`，不能再是 `public_temporary`；`autoScan.enabled` 必须为 `true`。接口里的地址标签若经过脱敏，不要为了对齐去把完整地址打到回复里。
5. 服务监听成功后会先扫描一次，之后每 30 分钟一次；已有刷新则跳过，不排队。配置节点每轮最多补 24 个小时档，3 天窗口大约 72 个小时起点，加上那 7 个需补读的完整小时，大约要成功跑完 3 轮才会补齐。未选中的更早历史留给后续批次，不得一次无界回补全历史。
6. 过夜必须守住磁盘和小时上限，失败要标明，不得把 Elysium 看板打空。真实故障按失败隔离处理，不要用提前截断整轮来「赶时间」。
7. 观察 `/api/v1/health` 的 `autoScan` 与 `refresh`，以及 `refresh_runs`。若出现 HTTP 429、日志区间被限制到约 10 个区块、或刚结束小时的起点状态又读不到，立即停下来汇报，不要靠无限重试硬撞。Alchemy 免费档的日志区间只有 10 个区块，不适合本场所生产扫描；当前配置按按量付费档使用。
