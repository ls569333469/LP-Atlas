让现有主站的 Meteora DLMM 六窗口数据正常显示，重点是手续费、fees APR、手续费环比、价格涨跌和资金效率。沿用官方 Data API、现有小时库及五分钟调度，不另建采集系统，不接 Raydium，不改 EVM 两链规则，不增加一批解释标签。

## 3. 手续费到底需要核对什么

这里只需回答一个问题：**官方历史 `fees` 是否就是普通做市仓位可分配的费用，已经排除了协议费、推荐分成与限价单独有费用？**

现有证据：

- 官方历史响应将 `fees`、`protocol_fees` 分开返回，但字段名本身不能证明两者还需相减。
- 此前 InputOnly 与 OnlyY 的少量完整5分钟成交样本，API费用与链上 `Swap2Evt.mm_fee` 的比例关系吻合；不能据此盲目再减一次协议费。
- 官方事件文档将 `mm_fee`、`protocol_fee`、`limit_order_fee`、`host_fee` 分列。限价单和推荐分成只与这一步费用归属有关，与资金效率无关。
- 本轮复查缓存交易发现一笔推荐分成非零：池 `5rCf1DM8LjKTw4YqhnoLcngyZYeNnQqztScTogYHAS6`，`mm_fee=2000`、`protocol_fee=178`、`host_fee=44`、`limit_order_fee=0`。这笔交易**尚未与对应完整时间桶的API费用对账**，不是已证明官方费用有错。
- 本轮缓存解码未取得非零 `limit_order_fee` 的对照证据。不能把“未取得样本”写成“官方一定混入限价单费用”。

建议最小核对：先复用已有原交易和官方SDK解码结果，对推荐分成非零桶做完整对账；再找非零限价单样本或官方明确的聚合定义，区分 `mm_fee` 与其他组成。不要重做全库交易扫描。若证据足以确认字段就是LP费用，直接复用已落库的 `reportedFeesUsd`，不再额外扣费，不需要新供应商。

若仍有特定分支无法证实，只列具体缺少什么证据及受影响范围，交复核决定；不擅自把“LP手续费”改成“官方费用”，也不为让页面有值而把未核字段当普通LP收益。

## 4. 统一计算口径

| 指标 | 本次应采用的口径 |
| --- | --- |
| 成交量 | 当前既定整点小时累计，较长窗口累加对应小时，不拿官方滚动1H冒充当前整点小时 |
| LP手续费 | 费用归属核定后的对应小时费用之和；不使用费率×成交量 |
| fees APR | 窗口LP费用 ÷ TVL × 年秒数 ÷ 窗口有效秒数；内部为比值，页面乘100显示百分比。当前未结束窗口用已过去时长，不能一律按完整窗口时长 |
| 手续费环比 | 按现行标准的对照窗口计算 `(当前费用−对照费用)÷对照费用`；3D的对照规则须核对现行标准，不在本次擅自改成另一套 |
| 资金效率 | 对应窗口美元成交量 ÷ 当前TVL，保持全站既定口径；不是年化，也不除以小时数 |
| 价格涨跌 | 复核官方OHLCV的价格含义与窗口边界后，按现行价格涨跌语义接通；未确认前不把X/Y兑换比冒充美元涨跌 |

OHLCV已在官方文档公开，支持1H，起止均包含。本轮 cbBTC/USDC 样本K线价格约59040–59932，与池内兑换价格同量级；这一例不足以证明 SOL 计价池也是美元价格。须至少再核一个非稳定币计价池及一个缺成交小时，避免只在USDC池上看起来正确。

## 5. 建议实施顺序与验收

以下为交给 Grok 的建议顺序，执行状态以05为准，不在此另维护勾选表：

1. **核定费用映射。** 用第3节最小对账得到可执行结论，明确字段是否需扣费、源版本及适用范围。先完成这一步，再接手续费和APR。
2. **补齐既有字段链路。** 在原适配器、小时表与SOL归一模块连接费用、六窗年化、环比；存量已保存的小时报告费用能复用就复用，不重拉全部历史，不修改EVM金额。
3. **核定并接价格边界。** 官方OHLCV可复用时，走同一请求预算和小时存储；核算新增请求量、耗时及失败处理，不另起调度器，不让价格请求失败阻塞成交提交。需要迁移时才新增最小字段。
4. **解决实际缺窗和加载问题。** 加载已有分页/缺小时补丁，按池核冷补是否正常推进；若实测存在失败池反复占预算导致后面的池饿死，再修排队，不凭假设扩建任务系统。
5. **一次完成实际验收。** 对最终发布数据逐池六窗核成交、费用、APR、环比、价格与资金效率；至少覆盖截图cbBTC/USDC、一个SOL计价池、一个新池和一个缺档池。实看搜索清空、切链、排序、翻页、详情及自动发布；复核EVM原行为。缺值逐项能解释，不以“全部有值”替代正确性。

预计涉及现有模块：

- `src/adapters/venues/solana/meteora-dlmm.ts`：费用映射、官方价格字段解析。
- `src/normalize/official-refresh.ts`：同一小时采集、补齐与诊断。
- `src/normalize/official-board.ts`：六窗指标归一，复用 `src/metrics/fees-apr.ts`。
- `src/shared/meteora.ts`、`src/store/types.ts`、`src/store/repositories.ts`：仅按最终字段需要补充；费用报告字段已存在，不重复建设。
- `src/web/src/SixWindowTable.tsx`：仅核展示接通，保持现有排版，不新增解释标签或新页面。
- 现有Meteora/窗口测试，以及确有必要的最小存储迁移。
