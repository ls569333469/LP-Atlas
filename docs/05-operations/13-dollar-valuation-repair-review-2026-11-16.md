## 2. 四个根因

1. **同资产别名不一致，属代码缺陷**。`prices.ts`在整次池遍历前后才shareNativePrice，且只补缺少的一侧。同一遍历中ETH、WETH分别取得价格后，两个都有值便永不消除冲突。已用现有函数最小复现，同一包装资产得0.25与1两种价格。08明确应视为同一ETH侧，修正不能任意选择最后出现或最大的价格。
2. **报价路径缺少已确认的主资产优先级，属待确认规则问题**。直接锚候选虽已读取，buildUsdPrices仍把所有活跃报价池按原始liquidity混排；首个可推出价格的路径获胜，已存在价格不会被更可靠通路覆盖。不同代币/精度池的原始liquidity不等同美元深度，三跳路径可先于直连生效。只把别名同步提前，可能使ETH与WETH一起错误，不能作为完整修复。
3. **缺少来源记录，验证指标不足**。锚校验只读USDG/WETH decimals，非ETH/USD预言机。usd_bridge_version=1只说明旧算法走完，不证明价格经济可靠；小时complete=1只证明区块覆盖。当前金额未记录可恢复的根价格/报价路径和来源版本，接口算术一致也不能证明计价正确。
4. **修复入口只补缺失，错误非空金额不会重算**。`repair-hour.ts`筛volumeUsd/lpFeesUsd为空，TVL也主要补空值；这些异常档已有数值、标记为1，不会因自动刷新自行修正。缺值修复与版本纠错应显式区分，不能先批量清空有效数据来强迫旧流程重扫。

补充边界：手续费仍是现有逐笔事件估算，历史协议参数和跨tick取整尚未精确重放；美元修正不把费用状态升级为精确确认，也不恢复用户此前暂缓的Hook独立分配研究。

## 7. 公开预言机价格源补核（免新增付费节点的候选）

用户要求优先考虑公开预言机，避免为主资产报价新增节点成本。本轮只读请求Hyperliquid官方 `POST https://api.hyperliquid.xyz/info`，请求体 `{"type":"metaAndAssetCtxs"}`，无需密钥，HTTP200，同时返回ETH、HYPE各自的oraclePx和markPx。若采用此来源，应使用oraclePx，不混用标记价格markPx。它是通过官方HTTP接口读取的预言机市场价格，不是本链上部署feed的历史区块调用，也不需要迁移Elysium公开RPC。

实时方案候选调整为：两链共用一次官方响应，取ETH与HYPE的oraclePx，再各自同步ETH/WETH、HYPE/WHYPE；跟随现有5分钟调度复用结果，理想无重试情况下总计288次HTTP查询/天，而非每链各288次。链上成交、池状态、储备仍用原RPC。该候选未接入生产、未测试长期可用性和实际账户/地区的限额；公开免密钥不等于无限请求或永久服务保证。

该响应本次未取得可对应每条价格的原始更新时间，收到响应的时间不能冒充预言机价格的发布时间。正式采用前核对更新时间/新鲜度能否验证、资产绑定、接口限额及失败恢复；实时与历史取价合同分别确定。此实测不证明该接口提供4天历史oraclePx，历史纠错仍须找到对应历史时点的可靠报价，Alchemy历史接口可保留为已验证候选，不能拿当前oraclePx回填旧档。

### 多链调用方式、更新频率与成本

业务链RPC继续各自读取成交和储备；后台独立读取公共预言机源，将已核资产美元价按资产ID与目标时间缓存，多链复用。读取HyperEVM或Ethereum的报价不代表启用该链产品场所。ETH/WETH共享一份价，HYPE/WHYPE共享一份价，合约映射沿既定资产核对要求，不按symbol直接套用到仿冒币、质押衍生币或任意桥接资产。

**五分钟读取不等于五分钟产生一条新价。** 本次RedStone HyperEVM清单的默认触发为偏差0.5%或心跳6小时，ETH/HYPE无单独覆盖；这是配置证据，不是运行服务保证。读取时携带真实updatedAt、目标区块/时间、价格小数位和来源，不能把请求接收时间当报价更新时间。本方案早期10分钟有效期只是未批准建议，与这种Push feed更新方式不能直接并用；应在来源合同中明确按官方心跳/偏差接受Push报价，或若产品必须每5分钟都有新报价，则改用经授权的更高频数据源，不能悄悄放宽时效或宣称本候选满足严格5分钟价格新鲜度。

## 9. 统一报价层落地设计（本轮方案正文）

### 9.1 交付目标和范围

在现有后台内建立供应商可替换、跨链复用、历史可追溯的主资产美元报价能力，解决错误多跳给ETH/HYPE定价、原生与包装币不同价、历史错误非空金额不修复三个问题。最终由真实新扫描和当前4天保留期的历史纠错共同验证，不以接通一家价格接口代替交付。

报价能力仍放在现有adapters、normalize、store、metrics四层中，不新增独立服务、数据库进程或第二套采集管线。浏览器不调用价格供应商或RPC。沿用五分钟调度、按链互斥、整点小时累计、六窗口、四天小时档保留、统一1H准入及现有费用算法；不增加交易功能、前端标签或额外监控定时器。

2026-11-16用户已追加授权：核对方案后暂停五分钟采集、更新代码，完成后恢复。此前只改文档的阶段已结束；实施只覆盖本节报价合同及既有小时纠错。RedStone Push来源、Push心跳/偏差时效和本期不接Chainlink备源已确认；包装映射已按9.12现场核定，完整保留期与真实验收已于17:23核对，具体范围及未恢复记录见05唯一清单。当前Elysium公开RPC和Robinhood已配置RPC继续各自采集，选择预言机不要求迁移这两个节点。

### 9.2 数据流与职责

```text
各链RPC / 官方索引 → 原币成交、费用、池状态、储备 ─┐
                                                   ├→ 现有美元计算 → 小时档 → 六窗指标 → API → 页面
公开预言机 / 其他已确认价格源 → 统一报价解析与缓存 ─┘
```

报价层按全产品设计，首次只接通已启用的Elysium和Robinhood；其余链保留现有占位。官方索引已提供的美元指标继续遵守各场所来源合同，不因增加统一报价层擅自覆盖其数值，亦不向索引场所强塞自建区块扫描。

| 模块 | 计划职责及现有接入点 |
| --- | --- |
| 主资产映射 | 服务端维护资产ID，以及链ID＋代币地址的已核映射；在src/shared提供必要合同，配置不放到页面组件 |
| 来源适配器 | 在src/adapters内接入已选预言机，只负责网络读取、精度及来源字段解析；每个来源一种实现，不复制成每条链一套 |
| 报价协调 | 扩展src/normalize/pricing-policy.ts，按资产、目标时间和来源合同取报价，处理去重、缓存、时效与已确认备源 |
| 池价换算 | 扩展prices.ts、price-bridges.ts，先锁定主资产价格，再计算长尾币价格；不另写第二份换算算法 |
| 保存与重估 | 复用src/store迁移、小时事务和repair-hour.ts，保存计价证据，显式重估旧版本非空金额 |
| 指标与发布 | 复用既有指标、按链发布版本及API；前端继续读取已提交结果，不新增报价轮询 |

### 9.3 资产身份和来源合同

资产ID按经济资产区分，例如ETH、HYPE、BTC、BNB、SOL；美元锚沿现有官方USDG/USDC合约规则。映射键必须包含链ID和完整代币地址，原生币用本链明确的原生标识。只有已核为原生币1:1包装的WETH、WHYPE才共用原生价格；不能将stETH、其他质押币、任意桥接币或同名代币自动视作同价。

每个主资产独立配置：主源及feed标识、源链/合约或HTTP端点、精度、更新时间语义、可接受时效、历史读取能力，以及可选且已验证的备源顺序。同一合约不能跨源链使用。主源和备源允许来自不同供应商；不同报价供应商不能在同一次计算中各自给ETH/WETH定价。

首期主源确定为RedStone Push，两条业务链共用ETH/USD、HYPE/USD。本期不接Chainlink备源，ETH已读通不代表HYPE具有对称备源。Alchemy Prices API只作可选适配，不因业务RPC采用Alchemy而定为主源；Hyperliquid及第1–8节先后建议只作调查证据。用户已确认各业务链维持当前实际节点配置，不迁移节点；Elysium沿用当前公开RPC，Robinhood沿用当前已配置Alchemy RPC，不将“均为Alchemy”的先前表述作为迁移指令。

已有证据的取舍如下：RedStone Push免密钥读通ETH/HYPE实时和4天前样本，但按偏差/心跳更新；Chainlink的ETH当前和历史已读通，HYPE未确认；Pyth、RedStone Pull需鉴权，套餐未核；Alchemy已核的两次最新报价请求为6.006秒和1.552秒，不是稳定耗时保证。供应商的统一选择须以本表能力核对为依据，不再凭单次最快或是否已买RPC定主源。

### 9.4 实时与历史统一的时间合同

调用方提交资产ID和targetAt。targetAt来自该链本次已选区块/状态截止，不能用全站最大截止代替本链；跨链小时同为整点也不能假定区块号相同。

每个有效报价至少保留assetId、USD十进制价格、sourceId、feedId、publishedAt、fetchedAt、sourceVersion；链上来源另带sourceChainId和sourceBlockNumber，供计价上下文引用。fetchedAt只表示请求接收时间，不冒充价格发布时间。解析校验在适配器入口集中完成，不在各池重复校验类型。

- 实时：选择publishedAt不晚于targetAt且满足已确认时效合同的报价；缓存样本时间晚于目标时不能直接复用。不同链targetAt不同时分别判断适用性。
- 历史：源链只选block.timestamp <= targetAt的区块，禁止取目标之后的最近块；在该块读取并记录真实publishedAt，且publishedAt <= targetAt；禁止用业务链区块号查另一源链，禁止用当前报价回填旧小时。Chainlink可按已核round读取；RedStone按已核历史区块读取，不假定其getRoundData保存了全部轮次。
- 不做价格线性插值，不取目标之后的最近样本，不将5分钟K线收盘价自动当成该周期起点价格。HTTP价格端点若只提供接收时间而无可靠报价时间，不视为已满足历史合同。
- 历史目标时点采用现有美元计价规则：该小时已提交结束区块/状态时点；不在本次修复改成逐笔成交时点美元估值。继续用原币小时累计重估美元，也不把五分钟不同价的美元段直接相加。
- 产品接受按RedStone Push心跳/偏差取得的最新有效价，如实保留publishedAt；不要求每轮都是五分钟内发布的新价。早期10分钟有效期废止，不与已核六小时心跳混用；读取更频繁不能刷新预言机自身价格。超出已核feed心跳或时间异常时不视为有效新价；心跳/偏差配置不等于价格误差或服务可用性保证。

### 9.5 缓存、并发与采集耗时

同一后台进程内共享报价能力，按来源＋资产＋目标区块/时间去重在途请求；按来源版本、资产和真实报价时间缓存结果。可按五分钟桶组织查找，但命中后仍须核publishedAt与targetAt，不能因落在同一桶就复用未来样本。价格缓存可跨业务链共用，池状态、储备、目录和扫描游标仍按链隔离。

报价与日志读取使用独立请求超时及并发资源，可并行但不得互相占满请求队列或锁；美元换算前等待所需报价；不按池发送请求，不重建全链目录以获取主资产价。某一资产获取失败不让另一无关资产等待其多次重试。

两资产每轮各读一次的基础量约576次/天，五资产约1440次/天，不含历史目标区块查找、重试等。公共Push节点两币并发约1秒只是小样本，不承诺增加固定1秒或稳定低于1秒。新增报价阶段计时和按来源请求计数，比较相同工作量下的完整链轮次，不再单独压测最大QPS。

价格查询使用独立于大日志请求的超时与有限重试配置，不继承360秒日志等待。建议候选为单次10秒、每个资产最多两次网络尝试（含已确认备源），实施时依已选来源核定并记录实际值，失败须快速结束且不得让ETH/HYPE互相等待；此为请求策略建议，不新增整轮强制截断。重试使用现有工具，不引入新并发框架或后台任务。

### 9.6 失败、备源与数据保留

仅按已批准主备顺序回退，并对备源执行相同资产、精度和时间合同；命中备源记录真实来源。不自动取最高价、平均价或最后成功供应商，不因两个来源不同价擅自设置新过滤阈值。尚未配置备源时明确记录无可用报价，不静默回到旧的任意多跳主资产定价。

报价失败不能阻止已成功取得的原币成交、费用及区块覆盖按现有原子提交规则保存和续接。所需美元字段按缺失处理，不能补0或把旧截止金额当新金额；旧发布结果沿现有保留机制提供，不能标成当前截止已完成。已有历史纠错失败时保留旧值与旧计价版本，不删除池目录、原币数据或将失败项标成已修复。准入仍执行既有三条件，不另加“没有某标签就删池”的产品规则。
