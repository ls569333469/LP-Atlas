# 失败重试、跨链与存储

失败怎么处理、跨链和兑换能做什么、库里存什么，这三项按路径分开，不得混用。全文与项目标准「失败、跨链与存储」一节一致。

## 失败重试

| 路径 | 重试规则 |
| --- | --- |
| 拉数与刷新 | 瞬时网络或节点失败可自动重试，次数有限并做退避。单链或单协议失败要隔离。仍失败必须明确报错；可以保留上次结果，但必须同时标明刷新失败和上次成功时间，不得冒充新鲜 |
| 签名前的报价与模拟 | 失败可在当页重新估算，不得自动提交交易 |
| 签名与上链 | 用户拒绝、模拟失败或合约回退，不得自动再发一笔。广播后状态不明时，先按同一客户端 ID 查链确认，禁止盲目重签重发。同一客户端 ID 不得生成第二笔开仓。用户看到失败原因后可主动再提交 |
| 兑换并开仓 | 尽可能组在同一笔；失败则整笔回退，不留下只换完没开上的半成品。找不到路径就明确失败，不默认改走第三方聚合器 |

## 跨链、兑换与数据获取

| 能力 | 规则 |
| --- | --- |
| 同链兑换 | 开仓缺资产时，只在目标链、已接入协议上找路径，尽可能与开仓同一笔、签一次 |
| 跨链 | 看板可跨链比较，分行展示。不自动做跨链桥或跨链兑换后再开仓。要在某条链开仓，资金须已在该链，钱包切到该链。跨链不能原子成交 |
| 仓位只读 | 同一 EVM 地址可在已接入的 EVM 链上只读汇总；Solana 仓位须另连 Solana 钱包 |
| 数据获取 | 全部由服务端拉取。第一期用归档节点和官方 StateView 自建窗口；后续链用官方索引或自建窗口。浏览器不直连节点或官方索引，不抓页面当真源。每个数字带来源和截止时间 |

## 存储与缓存

| 项 | 规则 |
| --- | --- |
| 库的角色 | 本地 SQLite 是服务端的分档缓存和看板读取库，不是链上状态的替代真源 |
| 写入 | 手动刷新与后台每 30 分钟扫描共用管线，由服务端拉源、汇总后写入。小时档设计保留 4 天（代码尚未同步），本期不做日档归并。不把全历史原始成交长期全留。同一范围同一时间只跑一个刷新 |
| 读取 | 看板默认读库中已汇总的结果。刷新进行中必须可见 |
| 失败与过期 | 刷新失败时若展示上次结果，必须同时标明失败和上次成功时间。禁止用过期数据冒充新鲜。仓位与开仓报价以链上读取为准，库只作带区块或时段的短缓存 |
| 变更 | 表结构变更必须走可重放的迁移脚本，禁止手改库文件 |

## 小时档保留与过期清理

设计将 SQLite 小时汇总保留期由 10 天改为 4 天，最长窗口为 3 天。当前 3D 与上一段 3D 共需 6 天，4 天不足以计算完整 3D 环比，缺档留空；当前 3D 数据是否齐全仍需核实。本期不做日档归并；不长期保存原始成交。此项尚未修改运行代码。

- 目标常量：`HOURLY_RETENTION_SECONDS = 4 * 24 * 3600`；完整两段 3D 理论跨度为 6 天，实际拉数及小时选择限制于 4 天保留范围。
- 截止时间对齐到小时：删除 `window_start < floorToHour(asOfUnix) - HOURLY_RETENTION_SECONDS` 的 `window_aggregates` 与 `scanned_hours`。看板「现在」优先用上次成功刷新的 `block_time`，清理也用同一时钟，以免误删当前回看。
- 同一截止时间之前的 `refresh_runs` 一并删除，但始终保留最近一次成功记录（`ok` 或 `partial` 且 `windows_built > 0`，与 `latestSuccessfulRefresh` 一致）。进行中的 `running` 记录不删。
- 不删除池和代币发现目录，也不删 `meta`。清理幂等，在每轮刷新记账结束后执行（成功、部分成功，以及已写入失败记录后）；若清理重入则跳过，且不得因清理失败让刷新失败。
