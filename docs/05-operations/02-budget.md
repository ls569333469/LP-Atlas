# 延迟与新鲜度预算

下表是设计预算例子，用来给每一段定额，不是测试得出的 SLA，也不是指南里那个 1.5 毫秒主链路的翻版。数量级按出块时间来定，而且必须按链分别计算：以太坊约 12 秒，Solana 约 400 毫秒至 1 秒，BSC 为秒级或亚秒级，以目标链当时出块时间为准。不能用以太坊的新鲜度阈值去卡 Solana 的行情。

| 环节 | 设计预算例子 | 说明 |
| --- | --- | --- |
| 行情解码与新鲜度判定 | ≤ 50 毫秒 | 超过该链约 1 到 2 个出块时间的行情禁止触发交易 |
| 头寸状态更新 | ≤ 50 毫秒 | 区间、库存、未领取手续费，留在内存 |
| 出区间或 Fee vs IL 信号 | ≤ 50 毫秒 | 只读当前必要状态，近似常数级 |
| 在线风控 | ≤ 20 毫秒 | 表驱动，结果只有通过或拦截 |
| 组包、签名、私有 RPC 发出 | ≤ 200 毫秒 | 这一段还在自己进程里，可以做预算 |
| 主链路到广播（不含确认） | ≤ 400 毫秒 | 目标是稳定且低于一个出块，不是 1.5 毫秒 |
| 上链确认 | 出块时间量级 | 按链分别计时和超时，不能用一条全局超时套所有链 |
| 旁路扫描、自建信号与聚合核对 | 数十秒至数分钟 | 发现和指标借用不走热路径 |

指标对齐方式：行情到决策、决策到广播、广播到确认分开记，并且按链打标签；P99 与抖动优先于平均值。RPC 要按链主备独立，单条故障的事故半径要有上限。

## 依据：为什么不能搬 1.5 毫秒

《高频量化套利架构与低延迟开发指南》里的 1.5 毫秒主链路预算，针对的是中心化交易所的下单路径。链上 LP 的约束是出块时间、Gas、滑点、MEV 和头寸状态。一笔撤池要等待被打包确认，不是微秒级下单可以压掉的。不要把 1.5 毫秒当成 LP 目标。稳定低延迟优于极限平均值，这一条仍然成立。
