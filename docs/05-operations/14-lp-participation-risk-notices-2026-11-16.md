# 14 LP 参与限制与风险提示方案（2026-11-16）

## 1. 目标与当前状态

按用户最新决定：不屏蔽池，不增加参与状态准入门槛。仅对满足现有统一 1H 条件的池补充风险提示，帮助区分“有权限干预”和“已经确认不能参与”。2026-11-16用户已授权按Grok复核修订方案并实施代码；当前实施与验收状态以05为准，金额、排序和采集口径保持；实施进度只在 05-roadmap 维护。

本方案取代聊天草案中“默认仅展示 lp_open，排除 lp_blocked/lp_unknown”和“先屏蔽 UNIWALL”的实施方向。不把旧稿继续当作执行要求。长期完整添加/退出模拟不列入本期。

有意取舍：保留排序意味着已确认不能参与的池仍可能按费用APR排在默认第一。风险提示只说明限制及收益归属，不解决排序占位，不得声称消除了该误导。

## 2. 保持的规则与范围

- 沿用 1H TVL ≥ $1,000、成交量 ≥ $100、手续费 ≥ $10；六窗口共用原准入池集合。
- 不改 fees APR 算式、费用状态、美元估值、排序、分页、五分钟采集、小时累计及四天保留。
- 多链通用身份为 chainId + protocol + poolId，不按代币名称、地址尾号跨链归并。
- 风险计算仅针对原规则已准入的 V4 池；无 Hook 的 V4 和 V3 不增加本功能风险标签，也不因此宣称安全。
- 不扫描全库 Hook、不增加独立定时器、不在浏览器调用 RPC。原始目录、成交和小时档全部保留。

## 4. 标签与证据模型

### 4.0 最终标签合同

主表使用简短静态标签。按2026-11-17用户要求，标签不提供点击、悬停或键盘展开解释，不增加浮层备注：

| 标签 | 触发条件 | 权限级解释 |
| --- | --- | --- |
| 可能有入场限制（橙色） | bit 11 或 bit 10 | Hook 可干预添加流动性或调整添加结算；不代表已确认禁止参与 |
| 可能有撤池风险（红色） | bit 9 或 bit 8 | Hook 可干预撤出流动性或调整撤出结算；可能阻止撤出或改变到账金额 |
| 交易结算可能调整（橙色） | bit 3 或 bit 2 | Hook 可调整交易结算；未核实是否实际额外扣费，不直接写“高税” |

纯bit 1使用“添加结算可能调整”，纯bit 0使用“撤出结算可能调整”，不归入入场/撤池类。bit 10/8回调即使没有ReturnDelta，也可能因revert阻止整个添加/撤出操作。beforeDonate/afterDonate本期范围外。

证据命中且适用版本匹配时，主表使用“已确认无法添加”“已确认无法撤出”，替代对应“可能”标签；不能只放详情或APR限定中。每池每类最多一个标签，同类多权限合并；详情保留具体权限与对应解释。单有 beforeSwap 不触发“交易结算调整”。标签颜色区分风险类型，不代表证据已确认。已核实结论在标签文案中明确“已确认”，不依靠颜色区分证据。

UNIWALL 仅按现有数据转换的结果是 `[可能有撤池风险] [可能有入场限制]`，证据等级 permission_only；它没有 ReturnDelta 权限，不显示“交易结算调整”。已核实源码结论作为另一层本地证据，不能声称数据库原本已有“已确认”状态。



### 4.1 权限能力：即时、无需 RPC

复用 `src/adapters/hooks.ts`，从已准入池的 Hook 地址解析：

| 权限 | 详情解释 | 含义 |
| --- | --- | --- |
| beforeAddLiquidity / afterAddLiquidity（bit 11/10） | 添加流动性可能受限 | 可以在添加前后拒绝操作 |
| afterAddLiquidityReturnsDelta（bit 1） | 添加结算可能被调整 | 可以调整添加时的结算，不等于禁止添加 |
| beforeRemoveLiquidity / afterRemoveLiquidity（bit 9/8） | 撤出流动性可能受限 | 可以在撤出前后拒绝操作 |
| afterRemoveLiquidityReturnsDelta（bit 0） | 撤出结算可能被调整 | 可能改变撤出结算，不直接称“撤出税” |
| before/afterSwapReturnsDelta（bit 3/2） | 交易结算可能被调整 | 不等于已经证实转账税或费用归属 |

多个权限合并为紧凑摘要，详情列出各项。afterRemoveLiquidity 回调本身可能拒绝撤出，但不直接认定可收税；无上述位不等于无代币转账门控。标签只描述实际检测范围。

### 4.2 已核实结论：少量证据覆盖能力提示

每项风险独立记录 evidenceLevel（permission_only / verified）、action（add / remove / settlement / fee_entitlement）、结论、来源、核对时间、目标链/池/Hook 和适用代码版本。未知不写成禁止，也不写成可参与。

本期用小型、可维护的证据配置，复用已有验证材料，不新建全库探测数据库或复杂任务系统。配置只标记已核实结论，不作为屏蔽名单。身份或适用版本不匹配则退回权限提示。代理或可变门控未经复核不能沿用永久确认；本期不承诺自动追踪升级，详情显示核对时间及范围。

ETH/UNIWALL 的确定项：Robinhood 4663，池 `0xa8f330994e5832b499e1c82921846f423a20ba7601fe9b42340715d2f81c8bd0`，Hook `0xbeF9c77eC3c1A0D92c4CB6264F8923B37a63EAE0`。Sourcify exact match 源码确认外部增减流动性回调无条件 Unauthorized；显示“已确认：外部无法添加 LP”，并说明费用由 Hook 收集分配，不代表外部 LP 可得。必要证据复用 outputs/fee-investigation/uniwall-hook-verified.json 与 uniwall-apr-comparison.json，实施前复核适用版本。

新项目由维护者或获用户授权的AI人工核实已验证源码或等价材料，记录 chainId + protocol + poolId + Hook + 适用代码版本、来源、时间及结论后，通过代码审查补录小型证据配置。未补录的新同类池只显示“可能”，仍可能排在前列。版本匹配以部署时人工核对并固化的本地版本绑定为范围，不新增运行时RPC；不自动发现升级，不能把静态匹配声称为实时链上验证。发现Hook/版本不匹配必须退回权限提示，重新人工核实后才恢复确认。

该池 APR 数值保留，但在其附近明确标注“池级费用年化，非外部 LP 可得收益”，不能只在隐藏详情说明。此为展示限定，不改金额或把 estimated 改成精确。

## 5. 数据流、模块与性能

在看板读取/归一化链路完成原有 1H 准入后，对准入池做纯权限解析，再合并少量已核实证据，经 shared 类型传入列表与详情；分页前后用同一结果。同池六窗口复用一次评估，不按每个指标/每个窗口重算。详情复用同一评估，不能出现列表与详情结论不同。前端只渲染结构化文案，不展示 RPC 错误、源码片段或内部调查备注。

预计涉及：

| 模块/文件 | 改动职责 |

### 5.1 不拖慢采集的硬约束

- 风险评估只在看板读取组装阶段执行，禁止接入扫描器、适配器拉数、池状态读取、报价、repair-hour、小时写入事务、游标提交和发布事务。采集结束不等待风险计算。
- 新增 RPC/HTTP 请求数必须为 **0**，包含 eth_call、源码查询、代码哈希验证、参考站API和证据更新。实施前人工核实与运行时行为分开；请求期间不联网核实证据。
- 只使用该次读取已有的池ID、链、协议及完整Hook地址；不得新增数据库查询、全目录载入/索引重建、池小时遍历、逐池文件读取或数据库写入。少量证据随模块加载一次。
- 复杂度按准入池数线性增长，纯位运算和内存匹配；同一构建不为六窗口重复评估。不新增调度器、后台队列、锁、轮询或逐池永久缓存。
- 采用普通返回值处理无证据，不捕获整条看板业务异常；证据配置缺项不影响金额/行展示。不以隐藏行或阻止发布处理风险未知。
- 用户明确不接受标签增加秒级处理时间。性能验收门槛：已过滤后的200个准入池，完整批次风险转换（权限解析＋本地证据匹配＋结构化风险字段生成）耗时不超过10ms；这是待实测的交付上限，不是已取得的结果。不得逐池分配10ms，也不得按六窗口重复计算。固定输入预热后连续测20批，记录各批耗时及最大值；任一批超限先定位修复，不以平均值掩盖超限，不带着秒级开销上线。
- 批次边界仅包括新增转换，不混入原有SQL、金额计算或网络等待。另对真实API固定输入进行开关对照，确认没有新增等待链路或秒级响应退化；不以整轮RPC波动代替纯转换计时。复用现有测试工具，不建设压测框架。
- 确认扫描调用图和写事务完全未新增风险工作；部署前后选相近正常增量轮次核对原阶段耗时、请求量及跳过情况。发现可归因于该功能的采集或API退化先修复，不靠加大线程/超时掩盖，不追加全库压测。
- 回退仅撤掉风险附加与展示，不触及金额、游标、报价和原有Hook文字。验证时不启动额外生产扫描。
