# 前端标准：多链池目录与大规模数据浏览

2026-11-13 用户补充：在原有三个 1H 门槛之后，排除 1H 手续费环比与价格涨跌同时为空（null）的池；任一指标有值（包括 0）则保留。此规则用于数据筛选，不代表诈骗鉴定；刚建池或比较数据缺失的正常池也可能被排除。六窗口共用筛选后的集合，长窗口缺档不额外删行；保留池目录与小时档，不改变采集及旧版 v1 接口口径。

版本 v1.3；2026-11-15（补充 PC 数据表格尺寸、对齐与信息层级标准；网络独立列按用户选定 A 版）。依据：用户要求按多链、多协议及约 1–2 万池规模设计，将布局、筛选排序、分页与稳定性讨论写入 DOCS。

数据规则见 [统一方案](../03-data/05-data-repair-and-1h-filter.md)：固定 1H 准入，LP 手续费 ≥ $10；展示和排序窗口共享池集合，六窗为 1H、2H、4H、6H、24H、3D。原六窗布局已按第 10 节落地；本次网络独立列及密度整改以第 11 节为准，正式实施尚未完成。

本文是项目标准的前端分类归档，不是平行方案。数据口径沿用 [看板信号与时间窗口](../03-data/01-signals-and-windows.md)，工程规则沿用 [代码标准](03-code.md)，开仓参数沿用 [开仓设计](../01-product/04-entry.md)。六窗接口、分页快照、多选和 URL 恢复已有实现；数据及交互通过不能代替视觉验收。用户本次确认替代原默认 36 独立列布局，唯一状态见 roadmap，不解除钱包、开仓阶段限制。

## 1. 范围与多链组织

- PC 优先，当前不继续手机适配。以全量池目录设计，不能以 Elysium MVP 的展示行数作为布局或容量上限。
- 首轮至少用 20,000 个池验证浏览容量。这个数量不是发现或采集上限，增加链与协议时沿用同一套目录与浏览路径。
- 一张看板跨链比较，一条记录对应一个具体池。同名代币、同交易对的不同链、协议、费率或池地址不得合成一个收益数字。
- 链、协议、接入状态由服务端目录下发，沿用 `src/shared/catalog.ts`，前端不另写固定链清单。已列入但未接通的场所明确标记，不显示假行情，不计入已接通数量。
- Barker 等参考站只借鉴界面与目录组织，不作为生产数据源，不照抄托管执行或费用策略。
- 本文不调整采集调度、场所启用与业务默认值。后台采集和浏览器轮询是两件事，本标准不新增浏览器自动轮询。

## 2. 布局与字段

### 默认池目录

每池一条记录，按预览在同一池行内纵排六项指标，方便跨窗口比较和翻页。公共信息保留交易对、链、协议、费率档、TVL、池龄、Hook；池地址 / poolId 可查和复制。动态费率按来源标记，不猜成固定费率。

六个窗口固定为 **1 小时、2 小时、4 小时、6 小时、24 小时、3 天**，窗口横排、每窗六指标纵排，不用互斥窗口标签代替六窗数据：

| 列组 | 内容 |
| --- | --- |
| 池信息 | 交易对、链、协议、费率档、TVL、池龄、Hook |
| fees APR | 六窗各自实际 LP 手续费 APR |
| 成交量 | 六窗各自 USD 成交量 |
| LP 手续费 | 六窗各自实际归 LP 的 USD 手续费 |
| 手续费环比 | 1H 至 24H 在数据完整时分别与上一等长窗口比较；3D 自身环比不作为必需指标，缺档显示「—」 |
| 价格涨跌 | 六窗各自涨跌幅 |
| 资金效率 | 六窗各自成交量 / TVL |
| 操作 | 详情；开仓实现解禁后再提供正式配置入口 |

每池保留 36 个数值位，布局为 6 个窗口列 × 每列 6 个对齐指标行；左侧池身份、网络、TVL/池龄、指标名称，加六窗口和操作，共 11 个物理列；尺寸与对齐以第 11 节为准。固定左侧池身份和顶部表头，保留表内横滚；各池六条指标行的顺序和高度一致。不再默认展示 36 个独立数值列，不靠缩小字体或只在悬停中显示主要值。

金额、百分比使用共享精度与单位规则，右对齐、等宽数字，缩写金额可查完整值。红绿只辅助表达，方向、缺档和异常同时有文字或符号。当前排序列突出，其余背景保持克制。

### 候选池对照

- 默认目录采用「六指标纵排 × 六窗口横排」，候选对照仍为独立按需功能；默认目录不能因此限制为仅展示 5 池。
- 在同一扫描工作区选择少量池后展开候选对照，上限仍为 5 个；默认目录继续按 50/100/200 池分页，不一次渲染全站池。
- 选择跨页保留，改变筛选不偷偷替换已选池；不可读取的池明确提示。仍以具体池为单位，不合并跨链收益。
- 返回目录保留筛选、排序、页码和滚动位置。矩阵不改变原值、来源与缺档状态。

### 配置面板

扫描目录优先使用工作区宽度。按 2026-11-13 用户补充，现阶段先显示可收起的右侧“新建仓位”占位区，收起后目录恢复全宽；点击池详情重新展开并显示当前池。开仓模板、滑点、授权、离场与执行规则沿用原标准，本文不重定策略。

## 3. 筛选与排序

2026-11-17现行：三项准入/漏斗/排序按[方案15](../05-operations/15-query-controls-and-funnel-design-2026-11-16.md)已选B实施；中央弹窗统一应用门槛和八项AND条件，手续费门槛默认10且可调，排序常显即时生效。下表旧费率选项口径以方案15百分数输入合同取代；单独漏斗及A稿已失效。

| 筛选项 | 规则 |
| --- | --- |
| 网络 | 默认全部已启用场所；全部网络与单链互斥，点击立即查询该链并回第一页，同步 URL；协议仍可多选 |
| 协议 | 默认全部已启用协议，可多选；与网络条件取交集 |
| 费率档 | 默认全部，支持固定档、动态费率，选项随目录和数据，不写死几个百分比 |
| 搜索 | 代币、交易对、代币地址、池地址 / poolId，按当前链协议范围查找 |
| 最低 TVL | 默认 $1,000，可改 |
| 最低 1H 成交量 | 默认 $100，可改 |
| 准入窗口及 LP 手续费 | 固定 1H，LP 手续费 ≥ $10；排序窗口独立选择 |
| APR 门槛 | 默认不设；设置时必须明确对应窗口，缺档不算达标 |
| 多条件漏斗（2026-11-16待预览确认） | 在原准入之后追加任意指标条件，全部同时满足（AND）。支持fees APR、成交量、LP手续费、手续费环比、价格涨跌、资金效率、TVL、池龄；每条独立窗口及 >、≥、<、≤、= 比较。百分比输入按页面百分数，金额按美元、资金效率按倍数、池龄按小时；TVL/池龄不分窗口。支持添加/删除、应用、重置及URL恢复，服务端全量过滤后分页，不在浏览器只过滤当前页。默认无追加条件，缺值不满足条件，不改变采集、根价、原准入或排序规则。折叠漏斗不取消已应用条件，摘要显示有效条件数。 |

不同条件同时满足才进入结果。同名 symbol 不是资产唯一身份；跨链同名代币不视为同一资产。无匹配组合时显示空结果，不自动取消条件或换链。筛选条件提供摘要或可移除标签；重置筛选恢复默认门槛，不暗中改变排序。

排序使用「指标、时间窗口、方向」三个控件，默认 **1 小时 fees APR 降序**。可排序指标为 fees APR、成交量、LP 手续费、手续费环比、价格涨跌、资金效率、TVL、池龄。

- 默认目录点击窗口表头，按当前指标快捷切换排序窗口，再次点击同一排序列反转方向。切换其他窗口保留指标与方向，控件、表头、当前排序说明同步。
- TVL、池龄不分窗口，窗口禁用并显示「不适用」；切回窗口指标恢复此前窗口。
- 显示例如「当前：2 小时成交量 ↓」，矩阵重点高亮指标与窗口的交叉值。
- **服务端对全部匹配池过滤排序后，才截取当前页**。严禁只排当前页或浏览器已下载的部分记录，再冒充全局排名。
- 相同排序值用稳定池标识作次级排序，保证顺序可复现；不是另增业务评分或用户多条件排序功能。
- 缺档 / 空值在升降序下都排最后，不按零处理。负数按真实值排序，未完成窗口必须标记。
- 准入固定按 1H，排序窗口独立选择，不改变统一池集合。

## 4. 分页标准

| 项目 | 规则 |
| --- | --- |
| 默认每页 | 50 个池 |
| 可选数量 | 50 / 100 / 200；服务端硬上限 200，不提供全量显示 |
| 翻页 | 第一页、上一页、当前附近页码、省略号、下一页、最后一页、输入页码跳转 |
| 控件位置 | 表格上方数量摘要与紧凑翻页，底部完整翻页；状态同步 |
| 页码 | 从 1 开始，输入仅有效整数，越界明确提示 |
| 改条件 | 筛选、排序、每页数量改变后回第 1 页；单纯翻页不改条件 |
| 定位 | 翻页后到表格顶部，保留横向列位置；从详情返回恢复原位置 |
| 空结果 | 显示符合条件 0 个池，禁用翻页，不显示可跳转假页码 |

示例：12,486 池、每页 50，共 250 页；首页 1–50，末页 12,451–12,486。数量由服务端返回，不将当前页行数当成全部数量。

摘要区分发现总数、匹配数、当前范围与页码，例如：「已发现 20,000 个池 · 符合条件 1,286 个 · 当前 1–50 · 第 1/26 页」。全量发现未完成时标明覆盖不完整，不声称已覆盖全站。

## 5. 翻页一致性与请求行为

### 数据版本

1. 首次读取关联已发布汇总版本，用逻辑 `snapshotId` 标识；在同一版本内过滤、排序、翻页。不能用每次请求开始的时间伪装快照。
2. 版本固定池集合、指标值、来源与截止时间。不能只冻结池 ID，却在后续页读取新数值；稳定次级排序同样适用。
3. 后台扫描结束且发布新汇总后，页面自动载入最新快照，保留当前筛选、排序和每页条数，回第1页。扫描过程中保留旧结果。
4. 手动刷新成功发布新版本后回第 1 页；部分场所失败须显示失败范围与实际截止时间。刷新失败保留旧版本并明确报错，不冒充新鲜。
5. 版本过期或重启后不可用，显示查询错误及“重试加载”；重试时保留筛选排序、回首页。不把旧页码静默接到新版本。
6. 优先复用现有 SQLite 汇总发布能力，不要求复制整库或新增数据库 / 通用快照平台。实施前明确保留时长、数量与空间上限，不无限保留；本次不猜定尚未实测的缓存参数。

### URL 与交互

URL 保存视图、链、协议、搜索、门槛、排序指标、排序窗口、方向、页码、每页数量；准入固定为 1H。刷新、前进后退和复制链接可恢复条件；快照失效按前述规则处理，不承诺历史行情永久回放。URL 不放密钥、钱包凭据或签名。

翻页、改排序、搜索只查询已汇总数据，不触发 RPC 扫描。搜索适度防抖；连续修改条件时取消过时请求，只让最新查询更新页面，避免慢响应覆盖新条件。

加载、失败、空结果分别显示。若保留旧表，保留它对应的旧条件与时间说明；不能给旧表贴新条件、新页码或新时间。失败提供主动重试，不无限重试。

## 6. 配套查询合同与性能约束

以下是全期正式实现需满足的逻辑要求；现行 `/api/v1` 已支持文末所列的可选分页合同，其余尚未全部支持。正式字段统一定义在 `src/shared`，遵循 API 版本和迭代规则。

| 请求 / 响应 | 必须包含的逻辑信息 |
| --- | --- |
| 请求 | 链协议范围、搜索与门槛、独立过滤 / 排序窗口、指标、方向、页码、页大小、可用版本标识 |
| 分页响应 | 当前页记录、匹配总数、发现总数及完整性、实际生效条件、页码、页大小、总页数 / 当前范围 |
| 版本信息 | 版本标识、发布时间，各场所实际来源与截止时间，不能用响应时间替代指标时间 |
| 场所状态 | 链 + 协议维度的未接通、刷新中、成功、失败、上次成功时间、缺档与告警 |

容量要求：

- 服务端校验页大小及查询参数，只返回当前页及必要元信息，不能把两万池 JSON 全发给浏览器。
- 过滤、排序、计数、分页使用同一版本和口径。按实际查询检查 SQLite 索引与执行计划，不能每次查询重算全历史或重新拉源。
- 浏览器只渲染当前页，翻页替换列表，不无限追加 DOM 或缓存所有旧页。200 池 × 36 个数值位最多 7,200 个指标项（窗口列内纵排），仍要实测布局与渲染成本。
- 详情、对照按需加载；不能每池默认创建图表、配置表单、钱包读取或独立计时器。控制在途请求和缓存数量，有限重试。
- 先完成服务端分页，不因存在两万条记录就引入额外框架。单页实测仍有瓶颈，再按工程规则评估虚拟列表等措施，不提前建设新服务。
- 当前栈继续 React + TypeScript + Vite、Node / Fastify 与 SQLite，不另起数据管线。浏览器不直接请求节点、官方索引或参考站。

## 7. 数据质量与故障显示

- fees APR 沿用实际归 LP 手续费口径，浏览器不重算真源公式。
- 每个数值可查来源、窗口起止、截止时间、完整性；共用元信息可放行或列组，但对应关系不能丢失。
- 单链单协议失败不使其他结果消失；旧结果标过期及上次成功时间。全局状态显示失败范围，不用一个成功状态覆盖所有场所。
- 缺档显示 —，真实零与缺档区分；未完成值有标记。异常 USD 计价遵循数据质量规则，不偷偷归零。
- 无匹配、未接通、加载中、缺档、查询失败和刷新失败是不同状态，不能一律显示没有数据。

## 8. 验证与实施状态

采用分页不等于已证明不会崩溃。正式交付需在目标 PC、浏览器及实际 Node / SQLite 部署上实测，记录配置、数据集、响应大小、查询耗时、操作到显示耗时和内存变化。合成数据只证明浏览容量，不能证明链上数值或采集吞吐。

| 检查 | 通过条件 |
| --- | --- |
| 分页边界 | 覆盖 0、1、49、50、51、20,000 行和末页；计数、范围、跳页正确 |
| 全局排序 | 高值位于原始数据末端仍进入第 1 页；全量跨页无重复遗漏，同值稳定 |
| 缺档负数 | 升降序缺档均排末，负值正确，1H 准入指标缺档不计达标 |
| 多链条件 | 多选组合、同名地址消歧、默认门槛、过滤 / 排序窗口独立均正确 |
| 版本一致 | 翻页中发布新版本仍保持当前结果；部分失败、版本过期、重启均有明确行为 |
| 快速交互 | 连续筛选排序、翻页取消请求，不显示过时响应，失败可恢复 |
| 浏览器容量 | 50/100/200 条均测；DOM 不随累计翻页增长，无标签页崩溃、持续无响应或无界内存增长 |
| 服务容量 | 最多 200 行响应，深页可读，不触发扫描；重复查询无持续资源增长，扫描中仍可读取已发布版本 |
| 可用性 | 固定表头与池身份可定位，横滚可读，键盘可操作，当前筛选排序页码可见 |

具体响应时间目标在实施前依据目标机器确定，测试前写明，不能测后降低门槛。本次两万池实际容量与 PC 操作结果记录在 roadmap 唯一清单，不作为固定延迟承诺。

实施进度唯一记录在 [更新迭代计划](05-roadmap.md) 的「前端目录与容量」项，本文件不另维护进度清单。现有 HTML 是交互预览，不证明正式分页、版本一致性或两万池性能完成。

## 当前窗口切换卡顿修复（2026-11-12）

用户反馈现行扫描页切换时间窗口卡顿，授权针对浏览性能修复，不扩大为五窗新布局或钱包实现。实测旧 24h 返回约 2.3 MB、1,500 多池，浏览器约 69,000 个 DOM 节点；旧页刷新中每 3 秒重读整表且未取消过时请求。

### 查询与响应约定

六窗请求沿用 `window` 表示排序窗口，增加 `includeWindows=all`；API 版本、返回模式、`sortField`、`sortDirection`、规范化后的链/协议集合、门槛及搜索组成查询快照键。`page`、`pageSize` 只控制冻结全量结果的切片，不进入快照键；`snapshotId` 用于定位和校验已有快照，也不进入查询键。TVL/池龄排序时窗口不生效，但仍返回六窗数据；不得借此重新按长窗准入。

六窗模式的响应在现有 `rows[]` 上增加 `windows: Record<WindowId, BoardWindowMetrics>`，单窗模式保持原结构；通过响应模式字段或共享类型区分，不能让原单窗调用被迫补齐六窗字段。原行级单窗字段在六窗模式中继续对应请求的 `window`，旧响应顶层边界也维持该窗口含义。每窗包含六项既有指标，保留各自 `MetricValue` 的来源、截止、完整性与原因；APR 所依赖的 TVL 保留现有计算语义，必要时随该窗提供，不在浏览器重算。响应共用窗口边界、发布版本和场所状态；值确实不一致的元信息须保留对应关系，不能用一个全局“完整”覆盖缺档。

当前查询快照属于特定排序条件；改变排序、筛选后回首页并取得新查询快照，不声称这些独立查询在后台发布变化时永远属于同一历史版本。同一次响应的六窗和其后续分页必须一致。多池对照须从同一版本取值，不能拼接来自不同发布截止的已选行。

### 落地核查修正与优化（2026-11-13）

以下记录实施前核查发现的缺口及执行约定；正式实现状态统一见 roadmap，本节不另设状态清单。2026-11-14 已实现下述存储身份隔离，实际生产接入仍待切换，见 Robinhood 专用说明。

1. **跨链身份须贯穿存储，不能仅修 React key。** `001_init.sql` 的 pools 主键是原始 pool_id，window_aggregates 主键是 pool_id + window_start；`repositories.ts` 的写入冲突键、`normalize/board.ts` 的 byPool 和候选集合也依赖原始 poolId。现有 Elysium 适配器使用原始地址或 V4 ID，并无链命名空间。因此现有占位不等于已能安全写入其他链。下一链写入前，须以规范 chain + protocol + 原始 poolId 为身份，贯穿仓储/聚合关联；2026-11-14 采用新场所内部 ID 命名空间实现该隔离，Elysium 旧 ID 保持兼容，无表结构变更，因此不新增 SQL 迁移；对外保留原始 poolId 用于复制和浏览器链接，不把组合标识发给 RPC。保留有效池与小时数据，不改写已应用迁移。当前前端迭代先统一接口和页面身份；存储改造属于新链接入前置，未完成时不得宣称多链真实入库通过。
2. **明确多选合同并保持旧调用。** v2 多选采用重复参数 `chains=elysium&chains=base`、`protocols=uniswap_v3&protocols=uniswap_v4`；旧单值 chain / protocol 继续支持。同维度同时提供单值和多值返回 400，避免隐含覆盖；空集合不发送，表示全部已启用范围。入口校验、去重并按稳定顺序规范化后，传给内部查询和缓存；URL 使用相同格式。目录中已知但未启用组合可见、标明未接通，默认不参与扫描；用户选中后不静默替换条件，无可查询组合则返回带场所状态的空结果。真正未知的链/协议返回 400。本次不增加 APR 等新的业务门槛控件，沿用已有六窗指标与固定准入规则。
3. **六窗元信息必须随窗口区分。** 增加 windowsMeta，按 WindowId 提供窗口起止及当前小时完整性；各场所另保留真实 asOf、来源和覆盖。复用 currentAndPreviousWindows、composeFromHours 和既有指标函数，不将 1H 改成最近已结束小时，也不把跨链截止强行对齐成新业务口径。3D 当前值和上一段分别处理；不为 3D 环比补采 6 天或扩大四天保留期。当前 72 小时不足时按原缺档规则显示，不删除 1H 合格行。
4. **冻结对象不等于读取期间天然一致。** 当前 readBoard 在读取前后复核 latestSuccessfulRefresh，pager 却在调用 read 前另取 revision；发布跨越读取时，缓存 revision 与返回数据可能不同。实施时由同一次读取返回实际数据版本供快照使用，不沿用提前读取的旧 revision。还须验证扫描尚未结束但已逐批写库时的行为：优先使用现有数据库能力建立一致只读事务，检查扫描写入/发布边界能否保证读到同一版本；结束轮次复核不能证明不存在中途写入混版。若现有写入方式不能满足，先定位最小读写边界修正并记录必要依赖，再实施，不以递归重试或复制整库代替解决，也不先建设新发布平台。运行中的 refresh 状态可实时更新，须与冻结的指标版本分开。实施核查：现有扫描已将 pendingWindows、pendingHours 与 finishRefreshRun 放在同一写事务发布；现有数据库初始化未配置 WAL，一致读事务期间提交写事务的真实 SQLite 用例出现 SQLITE_BUSY。最小修正为数据库初始化启用 WAL，使冻结读事务与原发布事务并行；不改变采集算法、发布事务或业务口径，并以并发发布用例验证。
5. **候选对照与详情复用同一快照。** 同一查询内跨页最多保留 5 个完整池身份；只读对照从该快照取值，不能根据已选 ID 查询最新数据再混入旧结果。必要时在现有 v2 查询路径按 snapshotId + 池身份读取最多 5 行，查询条件仍须匹配且不触发扫描。换筛选或排序后保留选择身份，但重新载入同一新快照的指标；未入选、不可读或快照过期须明确提示，不沿用旧数值假装同版。详情返回恢复 URL、页码和滚动位置；钱包开仓阶段限制不变。
6. **性能先减重复工作，再决定缓存调整。** 先按 1H 得到合格集合；一次取所需小时范围，对已合格池复用小时分组、代币资料及六窗计算，完成全局排序后分页。不能先分页再排序，也不能对每池或每窗各发一次目录/数据库查询。只读所需列和有效范围；查询计划及索引以实测决定。64 MiB 是 JSON 估算缓存上限，不等于 Node 实际内存上限；测量须包含序列化、structuredClone、并发不同条件查询和进程峰值。503 只是容量失败，不能要求用户缩小筛选来替代 20,000 池默认查询验收。
7. **按当前可交付范围推进。** 正式六窗 PC 目录先用已接通 Elysium 实际数据完成端到端验证，再用多链合成数据验证合同、身份和容量；明确二者证据范围。Solana 类型、存储和分场所截止属于其真实接入前置，不为了前端迭代立即重写 EVM 采集或宣称所有链已接通。现有 14 个占位全部保留，未接通状态展示纳入本次前端交付。
