# 代码标准

> 2026-11-16已确认RedStone Push统一报价合同见本文末节及方案13第9/9.10节。涉及主资产报价的旧描述已被该合同取代；报价层及历史纠错已部署，本轮统一验收及未恢复限制以05-roadmap“美元计价修复”为准。

> 最新设计：窗口为 1H、2H、4H、6H、24H、3D，小时档保留 4 天；实施状态及旧记录以 [统一方案](../03-data/05-data-repair-and-1h-filter.md) 为准，以下旧描述不代表已按新设计运行。

主系统用 TypeScript。Python 只做验证对照，Rust 只留给以后真正的高频热路径，不选 Go。第一期同一仓库：后端 Node.js 提供 HTTP API，前端用 React + TypeScript + Vite，共享类型放在 `src/shared`。包管理用 pnpm。Node.js 钉当前维护中的 LTS，并写进 `.nvmrc`。Web 框架与构建工具在仓库里钉死一套，不得并行再引一套。

## 共同约定

- 开启 TypeScript `strict`。禁止 `any`；确实需要时必须局部隔离并写明原因。
- 代码标识、文件名、API 字段用英文；界面文案用中文。一套到底，不得中英混用命名。
- 金额和价格全程用大整数或十进制库，只在展示层四舍五入。
- 前后端必须共用 `src/shared` 里的类型与常量，禁止各写一套再对字段。
- 密钥只放服务端环境变量，不进前端、不进仓库、不写进日志。
- 依赖和 SDK 锁定版本。EVM 用 `viem` 与钉版本的 Uniswap SDK；Pancake Infinity 用 `@pancakeswap/infinity-sdk`，不得拿 V3 SDK 硬套；Solana 用 `@meteora-ag/dlmm` 与 `@raydium-io/raydium-sdk-v2`。
- 统一用 Biome（或仓库钉死的同等工具）做格式化与静态检查，提交前必须通过。
- 目录：`src/adapters/`、`src/normalize/`、`src/store/`、`src/metrics/`、`src/web/`、`src/shared/`。HTTP 进程放在 `src/server/`，只作为 API 宿主。不得以重构为理由改已定切分。

## 后端

1. 服务端负责拉源数据、归一、存储、计算、过滤和排序，并对外提供刷新与看板查询接口。浏览器不得直接打官方索引。
2. 一个协议一个适配器，失败要能隔离。端点可配置，预留主备。索引挂了必须明确报错，禁止用过期数据冒充新鲜。
3. 池清单必须分页拉全。只存分档汇总，不得把全历史 swap 长期全留。
4. 看板统一准入接口为 `/api/v2/board`，旧 `/api/v1/board` 保留原筛选口径；健康和刷新接口继续使用 `/api/v1`。响应里每个指标带来源与截止时间。看板查询须预留按链、协议、费率档、交易对或代币搜索，展示与排序可选择时间窗口。`POST /api/v1/refresh` 可带可选的链和协议范围。破坏性变更必须走迭代流程并升主版本；`0.x` 在第一期验收前允许一次性调整 `/api/v1` 形状，之后破坏性变更升主版本。
5. SQLite 表结构变更必须有可重放的迁移脚本，禁止手改生产库文件。
6. 日志记失败原因、数据来源和耗时，不得打出密钥、钱包或完整请求身份。
7. 后端框架钉死 Fastify（或仓库已钉死的同等框架），不得再并行引入第二套 Web 框架。

## 前端

1. 前端只负责展示、筛选交互、自动载入已发布结果和现有服务端刷新入口。过滤与排序以服务端结果为准，前端不得另写一套 fees APR 公式当作真源。
2. 禁止浏览器直接请求官方索引、节点、The Graph、Alchemy、区块浏览器或 Uniswap 官方接口。
3. 前端做成应用壳：看板是其中一页，预留池详情、开仓和仓位路由，第一期不做假的空页面，也不连接钱包、不做登录页；按已授权五秒状态轮询自动载入新发布结果，轮询不触发采集。界面布局可对照参考站，但要达到可日常使用的完成度，不照抄托管执行。
4. 每个数字必须看到来源和截止时间；未完成的小时、非官方来源、hook 类型必须可见。缺档显示为空，不得用邻近窗口凑数。
5. 门槛、默认排序和列定义不得写死在组件里，必须走共享常量或接口返回的配置。
6. 同一交易对分行展示。不得只用颜色区分状态；表格应可被键盘阅读。
7. 界面文案用中文。加载中、失败和空结果要有明确说明，失败不得静默落回成旧表。

多链目录、PC 布局、分页、全局排序与容量要求见 [前端标准](07-frontend.md)。v2 可选六窗响应、分页及有界快照已有实现；2026-11-13 用户确认默认 PC 页面整体按指定 HTML 预览对齐，包括六窗横排、每窗六指标纵排，当前正式视觉尚未完成。实施与验证范围以 roadmap 唯一清单为准，新链真实入库仍有独立前置。

## 测试与质量

- 计算层（fees APR、窗口对齐、过滤排序）必须有单元测试；适配器必须有钉死的官方响应夹具测试。
- 金额精度与口径测试必须覆盖：动态费、协议费、缺档、未完成小时。
- 测试框架钉 Vitest（或仓库钉死的同等工具）。提交前测试与静态检查必须通过。
- 禁止把真实 API 密钥写进测试；禁止测试直接打生产索引。

## 面向全期的结构预留

前后端按整个产品来设计，不为「只够第一期跑通」把类型、接口和页面写死。第一期验收目标为 Elysium 上的 Uniswap V3 与 Uniswap V4；2026-11-14 用户授权的 Robinhood 并行接入例外见 `08-robinhood-venue.md`。后台同一五分钟调度器按链互斥续接采集，与现有刷新入口共用管线；不提前实现暂缓项（Fee 对 IL 列、提醒、自动开仓）。钱包、只读仓位和开仓页先完成设计，实现须等扫描验收通过，不得提前写进产品代码。但共享类型、HTTP 接口、存储和前端壳必须能原样接上下一期，而不是每加一条链就改合同。

已规划但尚未接通的能力，用目录、可选过滤字段和预留路由占位，不得用假数据或空页面装成已经做完。

### 目录，不要写死当前两条

- 链与协议以「已启用目录」为真源，由服务端下发。标识用稳定英文 id（如 `elysium` / `bsc` / `ethereum` / `base` / `solana`，以及 `uniswap_v3` / `uniswap_v4` / `pancake_v3` / `pancake_infinity` / `meteora_dlmm` / `raydium_clmm`）。新增目标协议只加目录项和适配器。后期协议（Base 上 Pancake 的现行官方协议、Meteora DAMM V2）轮到时再加入目录并单独写适配器，不提前启用。
- `ProtocolId`、发现数量、刷新统计不得写成只有 `uniswap_v3` 与 `uniswap_v4` 两个字段。发现数量和刷新计数按「链 + 协议」汇总。
- 健康检查与看板响应描述当前启用的全部场所和各自节点来源，不得只返回一个 `chainId`、一个 `rpcSource`。
- 指标来源类型预留官方索引与自建两类（以及标明非官方的备源），不得把来源写成只能是自建。联调使用官方公开节点时，须标成临时公开源（public_temporary）。
- 界面顶栏、筛选项和协议文案跟目录走，禁止在组件里写死「Elysium · Uniswap V3 / V4 · 第一期」。只有一条链启用时，链列可以收起，但字段仍在合同里。

### HTTP API

看板查询支持按链、协议、费率档、代币或交易对搜索；展示与排序窗口为 1 小时、2 小时、4 小时、6 小时、24 小时、3 天。默认全部已启用场所，以 TVL ≥ 1,000 美元、1H 成交量 ≥ 100 美元、1H 归普通 LP 手续费 ≥ 10 美元统一准入，各窗口使用同一池集合；默认按 1H fees APR 降序，不设 APR 门槛。`/api/v1/board` 和 `/api/v2/board` 均停用 7D，`7d` 请求明确返回 HTTP 400，不静默映射至其他窗口。

`POST /api/v1/refresh` 可带可选的链、协议范围；省略则刷新全部已启用场所。不得做成只能刷新 Elysium 全量这一种请求。

统一 1H 准入为口径不兼容变更，已按统一方案使用 `/api/v2/board`；六窗模式通过可选 `includeWindows=all` 增量提供，保留原单窗字段。v2 多选使用重复参数 chains / protocols，池身份在接口与页面使用 chain + protocol + 原始 poolId；原始 ID 大小写保留。快照在一致读事务内取得实际发布 revision，SQLite 使用 WAL，不改原扫描发布事务。后续破坏性变更仍须按迭代流程处理。

### 存储

- 代币以 `(chain_id, address)` 为主键，禁止只用地址。
- 池、窗口汇总、刷新记录从第一期起就带 `chain_id` 与 `protocol`，刷新统计不得拆成 `pools_v3` / `pools_v4` 这种到了下一期就要改表的列。
- 表结构改动走可重放迁移，不得手改库文件。

### 前端壳

- 看板是应用里的一页，不是整个应用。为后续页面预留路由：全站看板、池详情、开仓、只读仓位。未开工的路由不做空壳页面，也不放入口装成已上线。
- 第一期窗口切换、链 / 协议 / 费率档筛选、交易对搜索，属于已定看板能力，应做在看板页里，不要等「以后再加一层新应用」。
- 过滤、排序、窗口和目录以服务端为准。浏览器仍然不得直接打节点、官方索引或第三方数据接口。
- 以后加自动刷新或钱包时，只在已解禁后接入现有壳与 `/api/v1`，不得另起一套前端数据源。开仓层实现时，组交易和签名请求走独立模块，不得把钱包逻辑写进看板组件。


## 统一报价工程合同

2026-11-16用户已确认的报价合同见[方案13第9/9.10节](../05-operations/13-dollar-valuation-repair-review-2026-11-16.md#9-统一报价层落地设计本轮方案正文)，取代此前Alchemy作为主源、Hyperliquid作为主源及10分钟有效期的调查建议；原文相关旧计价描述只说明旧生产状态，不作本次实施规则。2026-11-16用户追加授权停采集更新后恢复，RedStone代码与迁移012已部署，17:08补丁加载至API27116；包装映射、完整保留期及本轮真实验收已核，未恢复记录和精确费用限制保留；唯一进度见05-roadmap“美元计价修复”。

- 在现有四层内实现统一报价能力，不另起服务/扫描管线。主源RedStone Push，两条已启用业务链共用ETH/USD、HYPE/USD；报价按资产＋来源＋目标时间共享，池状态、目录及游标按链隔离。各链采集RPC维持实际配置，本方案不自动迁移到Alchemy；Alchemy Prices API仅可选适配，本期不接Chainlink备源，不假设备源资产覆盖对称。
- 接受Push心跳/偏差的最新有效价，如实记录publishedAt；不要求每轮五分钟新价，不混用早期10分钟有效期与六小时心跳，不靠加频读取刷新预言机。源链历史块必须block.timestamp <= targetAt，报价publishedAt也不晚于targetAt；五分钟桶命中仍核时间，禁止跨链套区块号、未来最近块和当前价回填历史。
- 仅已验证1:1包装的WETH/WHYPE同价；本轮仅核定Elysium官方WHYPE和Robinhood官方WETH（地址及相同运行代码证据见13第9.12节），其他映射未启用；同名币、质押衍生币及任意桥接币不得自动串价。根价先锁定，池推导不得回写，同一计算内原生/包装引用同一值。
- 复用原币累计及repair-hour按小时重建价格表，重估旧版本非空错误金额，不重拉全部Swap、不统一倍乘。TVL仍依赖业务链历史储备；修复不得覆盖较新续接，失败保留旧值及旧计价版本。金额、来源引用/计价版本、链发布版本沿小时事务提交。
- 报价失败不得阻止原币成交、费用和覆盖提交；美元缺失不补0、不把陈旧金额标成当前完成。价格使用独立超时与请求资源，不继承360秒日志等待，有限尝试后快速结束，不与日志或另一资产互相阻塞。关闭新报价不得静默恢复已证实错误的旧多跳为正确值。
- 不改变费用算法、窗口、保留期、准入、前端布局或未启用场所。实施/部署授权与文档合同确认分开记录，不因本节写入就标记代码或金额验收完成。
